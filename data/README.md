# `data/` — regenerated (derived) content

Most files here are **derived** from the live GitHub API / build scripts and are
**gitignored**. They are regenerated on every Pages deploy by `hugo.yml`; do
**not** hand-edit them — local changes are overwritten on the next build.

| File | Source script | Tracked? | Regenerated by |
|------|---------------|----------|----------------|
| `github.json` | `scripts/sync-github.cjs` | ❌ gitignored | `hugo.yml` step "Sync GitHub repos + gists" |
| `crosslinks.json` | `scripts/build-crosslinks.cjs` | ❌ gitignored | `hugo.yml` step "Generate cross-links" |
| `static/data/knowledge-graph.json` | `scripts/build-knowledge-graph.cjs` | ❌ gitignored | `hugo.yml` step "Rebuild Knowledge Graph" |
| `static/data/ontology.json` | `scripts/build-ontology-feed.cjs` | ❌ gitignored | `hugo.yml` step "Generate ontology feed" |
| `authors/` | hand-authored | ✅ tracked | — (edit directly) |

## Freshness model
- `sync-github.cjs` writes `data/github.json` with a `generatedAt` ISO timestamp
  and a `stats.errors` count. It is **graceful**: per-repo/gist failures are
  caught, and the file is always written (`process.exit(0)`), so the deploy
  never ships a missing/broken index — worst case it is partially empty after
  an API/rate-limit hiccup, then refreshed on the next run.
- `build-crosslinks.cjs` / `build-ontology-feed.cjs` emit valid (possibly empty)
  JSON when `data/github.json` is absent, so the build still succeeds.
- `build-knowledge-graph.cjs` reads `data/github.json` (repos/gists) and the
  post corpus to emit the knowledge graph. It is consumed by the client at
  `/data/knowledge-graph.json` (Hugo copies `static/` to the site root).

## Local dev
To populate derived data locally before `hugo`:
```bash
node scripts/sync-github.cjs
node scripts/build-knowledge-graph.cjs
node scripts/build-ontology-feed.cjs
node scripts/build-crosslinks.cjs
```
A fresh clone without these steps still builds (downstream scripts tolerate
absent derived files); the knowledge-graph visualization and repo/gist pages
simply render empty until synced.
